# PeekPeak Divergence Register

Any implementation change that diverges from `spec.md` or `review-rules.md` MUST be
recorded here with status. RULED entries take precedence over the spec; OPEN entries
block nothing but must be resolved before mainnet.

| ID | Title | Status | Summary |
|----|-------|--------|---------|
| DIV-D-1 | Failure-path soft-exit semantics | RULED | SPEC-5's original "revert the whole tx on target revert" cannot persist the `consecutiveReverts` counter or the deactivation (a revert rolls back all state). Ruled: failed-target and depleted-escrow paths SOFT-EXIT - the registry tx succeeds, protective state persists, client never charged, executor never reimbursed for failed work. Executor's own tx gas is the only loss and only authorized executors (pre-simulating watchers) reach it. RULE-4 amended accordingly: "failed work charges nobody but the party at fault." |
| DIV-D-3 | Pricing: flat keeper tip replaces percentage premium | RULED | Owner-directed (2026-09-23): deprecate the 15% gas premium. Successful executions charge exact gas reimbursement (gasUsed x tx.gasprice) + a flat keeper tip, default 0.005 AVAX, owner-settable via setKeeperTip bounded by MAX_KEEPER_TIP = 0.05 ether. Tip routes to treasury. Solvency precheck and registration minimum become (gasLimit + 2*OVERHEAD_BUFFER) x gasPrice + keeperTip. Failed/reverting executions still charge nothing; checkJob statics remain free. |
| DIV-D-2 | Solvency formula includes buffer gas | RULED | SPEC-5.2's `gasLimit * tx.gasprice * (1+p)` omitted the registry's own overhead gas: for small gasLimits the 15% margin does NOT cover `OVERHEAD_BUFFER * gasPrice`, so `totalDeduction` could exceed the prechecked escrow. Ruled: precheck = `(gasLimit + 2*OVERHEAD_BUFFER) * tx.gasprice * (10000 + premiumBps) / 10000` (superseded by DIV-D-3's flat-tip formula). More conservative (higher required), makes the defensive shortfall branch unreachable. |
| DIV-D-4 | executeJob payload size cap | RULED | Audit remediation F-2 (2026-09-25): measured `gasUsed` includes the `execPayload` calldata->memory copy, which the solvency model `(gasLimit + 2*OVERHEAD_BUFFER) * gasPrice + keeperTip` does not cover; an unbounded payload (job-owner-controlled via `checkJob`'s return) could push a successful execution into the "defensive" shortfall branch - target work done, nobody charged, executor eats the gas. Ruled: `executeJob` reverts `PayloadTooLarge()` for `execPayload.length > MAX_EXEC_PAYLOAD = 4096`; at that cap the copy+expansion cost (~2.3k gas) stays within the `MIN_OVERHEAD_BUFFER` (10,000) slack, so the `gasUsed <= gasLimit + 2*OVERHEAD_BUFFER` bound now holds ON-CHAIN for every allowed buffer and the shortfall branch is genuinely unreachable. RULE-11 amended. |
| DIV-D-5 | OVERHEAD_BUFFER upper bound at construction | RULED | Audit remediation F-4 (2026-09-25): constructor now enforces `MIN_OVERHEAD_BUFFER <= overheadBuffer <= MAX_OVERHEAD_BUFFER` (500,000 = 10x the calibrated 50,000 default). A fat-fingered buffer previously failed silently - jobs stayed registrable and every execution overcharged the escrow within the precheck; misconfiguration now fails loud at deployment. Applies to new deployments (registry is immutable; the Fuji pilot keeps its 35,000 buffer). |
